# 全项目开合动画与底部窗口复查

日期：2026-10-28。基线：`20ee348`（6.0.1）。

## 验收范围

本次用户补充了两项明确要求：说明、公式等展开／收起也要有过渡；分享、预览、选择器、保存到项目等底部子窗口统一左右贴边、底部贴屏、仅顶部圆角，保留安全区和键盘避让。

以 `app.json` 的 28 个注册页面为清单，检查页面进入／返回、子窗口打开、关闭按钮、遮罩、取消、选中、确认、保存成功、快速重复操作、后台与卸载清理。微信系统导航、系统确认框、原生 picker、系统图片预览和分享面板使用平台自己的动效。居中确认框、灯具卡片的定位浮卡不改变用途。

不修改核心算法、产品资料、数值基准或持久化数据。保存和计算仍按原语义完成，不能依赖动画计时器才执行。

## 发现和修复

1. **原生弹层先删内容。** 增益结构、限幅器使用 `page-container` 时，关闭标志同时删掉内部面板，原生退场只剩空容器。改为先让容器退出，等 `afterleave` 再卸载内容。选择型号、项目面板、分享图片、说明和原生返回使用相同生命周期。
2. **生成中关闭时内容跳变。** 关闭分享窗口会先取消图片生成并立刻切换加载视图。现在先使旧任务失效，保留退场中的内容分支，退出完成后统一清理。
3. **成功操作绕过动画。** DMX 的选灯具、批量添加、确认变更、保存项目及灯位布局应用／缩减改为经过关闭流程。保存后的上下文切换保持同步，切后台也不会丢失已完成的结果。
4. **计时早于视图提交。** 控制协议、SPL、项目重命名、通道与线缆、DMX 的相关阶段从 `setData` 完成回调开始计时，并检查旧回调、重开及销毁状态。另修复浮卡旧打开回调可能清空新关闭计时器的竞态；回归保留了关闭途中强制触发旧回调的场景。
5. **展开／收起直接切换。** 新增共用的 210ms 高度与透明度过渡，使用内容自然高度；没有固定最大高度。保留减少动态偏好和关闭态辅助功能标记。
6. **同类底部窗口形态混用。** 按用户选择统一贴底，安全区移入面板内容区域，检查外层 padding、最大宽度、底部圆角和内联样式的覆盖关系。
