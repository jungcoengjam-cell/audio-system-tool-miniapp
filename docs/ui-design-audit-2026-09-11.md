# 主要功能 UI 设计审查

审查日期：2026-09-11。范围是八个计算工具、工具入口，以及项目页的入口组织；本轮不修改功能源码。

## 判断

需要优化，优先处理显示正确性、参数可读性和功能可发现性。现有的共享浅深主题、自动计算、主要数值突出、图解按需展开和结果操作框架已具备基础，不建议全站更换视觉风格或把每个计算页都改成多步骤向导。

本轮以正式源码为依据，使用真实页面初始数据和 WXML/WXSS 生成了工具入口与八个工具的浅深主题模拟截图，共 18 张。模拟宽度为 375 逻辑像素，不含微信原生导航、键盘、原生选择器与 Canvas 绘制；截图中的输入控件边框也可能与微信原生控件不同。下列缺失绑定为代码事实，尺寸为源码和浏览器模拟证据，误触率及阅读效率仍需真机验证。

## 优先处理

### 1. 摄像机型号信息缺失：显示正确性问题

`pages/camera/camera.wxml:20–21` 仍读取 `cameras[cameraIndex].model/category/sensor`，选择器底部第 225 行还读取 `cameras.length`。但 `pages/camera/camera.js` 的 `data`、初始化及计算后的 setData 均没有提供 cameras。

本次捕获 onLoad/onShow 后的数据并复现：型号栏仅剩“· 机械云台 ·”，结果中仍能看到 TV-6124HK，说明计算可执行但当前所选设备的输入反馈丢失。这会影响用户确认正在使用哪个型号。

建议：提供轻量的当前选中摄像机展示信息及可选型号数量，模板读取这些字段。无需重新把完整型号库塞入页面数据，也不改变光学计算。验收需覆盖初次进入、切换型号和打开选择器。

### 2. 工具入口的音频功能容易被漏看

`pages/tools/tools.wxml:9–20` 将五个音频工具放在无滚动条的横向区域；当前 375 宽模拟中，首眼只看到增益、限幅、声压级，会议室和线材需要横滑。视频两张、灯光一张则在整行中留下较多空白。

建议：改为紧凑、固定位置的工具卡片网格，领域标题保持轻量，确保八个工具通过纵向浏览均可发现。工具页服务于快速定位，保留探索页的横向文章浏览方式。验收重点是首次使用者能否找到会议室和线材入口，不要求再增加搜索或收藏体系。

### 3. 统一实际触控区域和关键参数字号

源码中存在 64–80rpx 的选项区域。375 宽模拟测得：摄像机部分选项约 33–36px、线材模式约 37px、DMX 工作区页签约 36px、会议室等级约 32px。它们仍可点击，但现场单手操作容错偏小。

建议：保留紧凑视觉的同时扩大可点击区域；按最窄支持机型验证 44×44 逻辑尺寸目标。88rpx 只在 375 宽时相当于 44px，不能当作所有屏宽的通用保证。项目 DESIGN.md 与 [Apple 按钮指引](https://developer.apple.com/design/human-interface-guidelines/buttons) 都强调足够点击区域和主要操作的视觉层级。这里使用 Apple 指引作设计参考，不将其称为微信强制规范。

三列参数中较重要的标签和值仅约 20–21rpx，应优先扩大字号、允许合适换行或改成两列。不要靠进一步缩小文字来塞入更多信息。

## 八个模块的调整建议

| 模块 | 结论 | 最值得调整的内容 | 应保留的优点 |
| --- | --- | --- | --- |
| 摄像机 | 优先修复，局部优化 | 修复型号绑定；放大场景/高度选项；自定义分支增加“参数来源”分组标签 | 距离和高度并列的主结果、安装示意及计算过程按需展开 |
| 限幅器 | 优先优化输入 | 功放模式、灵敏度、HPF 三列过密，改两列或适应窄屏；无效负载提示明确关联数量/连接/模式 | 阈值是第一视觉重点，次级电气指标已分组 |
| 增益结构 | 中等优先 | 将“在哪里执行、设置多少”组织成清晰操作行；长解释由右对齐窄列移至下一行；增大目标峰值选项小字 | 一次衰减原则，以及现有跳转限幅/声压级的现场流程 |
| LED 大屏 | 中等优先 | 让含包边安装外尺寸与净屏同样容易找到；输入中 m 与 cm 的区别更清楚；窄屏检查三个预留字段 | 当前推荐尺寸、观看条件与比例示意已经分区 |
| 声压级 | 小幅优化 | 当前输入框显示范围/错误状态；降低听感/会议参考长句的视觉权重 | 主 dB SPL 数值、当前测点和距离表已明确 |
| 线材选型 | 小幅优化 | 模式附上已有数据中的“100 V 广播喇叭线 / 定阻金银线”语境；错误提示靠近相关输入组 | 推荐规格、公司表格依据和公式复核路径完整 |
| 会议室扩声 | 基本结构保留 | 扩大场景/等级选项触控区域；展开依据减少重复指标；需要时补一行场景适用说明 | 摘要先行、选型依据与布局图折叠，首屏没有全展开复杂图解 |
| DMX 编址 | 基本结构保留 | 地址方案错误卡可直接返回配置；复核 A–D 域标签的小字和窄屏排布 | 配置/方案工作区、按域/分组查看、批量操作与位置图已有分工 |

增益页当前长句在 375 宽模拟下没有溢出，因此属于扫读效率优化，不列为阻断性缺陷。LED 三列预留也未在本次 375 宽模拟下出现明显截断，列为窄屏验证与单位可读性优化。DMX 通道入口外层已有 88rpx 点击高度，不把伪元素的较小视觉尺寸误判成实际点击区域缺失。

## 跨模块的结果与错误呈现

- 各页自动计算应继续保留。无需为统一样式再增加一次“计算”点击。
- 结果以“一项主要结论 + 必要执行值 + 条件/边界 + 依据”组织。每种工具的任务不同，不必把所有结果硬塞成同一张四格卡。
- “生成图片、复制、收藏、加入项目”已有共享样式。可以统一在主要结果附近的操作位置，避免在长说明或距离表之后才能找到；不必为简洁而隐藏用户常用的复制。
- 输入错误应就近关联字段或字段组；保持既有校验条件和防抖，不在用户短暂编辑中间态时反复弹打断式提示。
- 项目 Tab 当前默认打开“常用收藏”，而“现场项目”需要二次切换（`pages/projects/projects.js:33–34`）。这是命名与默认视图是否匹配的产品取舍，可在后续观察使用频率后决定，不作为本轮必须修改项。

## 建议实施顺序与验收

1. 摄像机显示绑定：型号切换前后信息完整，结果对应正确型号，页面数据仍轻量。
2. 工具入口与共享输入规范：八个入口可发现；窄屏关键字段不截断；主要点击区域达到预定尺寸。
3. 限幅、增益与 LED 的局部布局：用户能快速读出需要设置的值或需要核对的安装尺寸。
4. 错误就近反馈、结果操作位置统一：修改错误无需寻找字段；复制、图片和项目操作可快速定位。

后续开发应验证 320/375/430 宽度、浅深主题、长型号、空值/非法值、切换模式，以及真机键盘弹出后当前输入的可见性。涉及共享样式时扩大回归范围；动画帧率、毛玻璃和 Canvas 性能单独做真机检查。
