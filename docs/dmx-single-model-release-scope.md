# DMX 单型号灯组添加范围

本版本的灯组添加流程按单次操作选择一个灯具库型号。用户从“＋ 灯组”打开灯具库，选择一个型号，再选择该型号支持的通道模式和数量；确认预览后写入方案。一个灯组可包含多台相同型号灯具，也可以重复添加灯组。

本版本不提供在同一次添加操作中同时选择多个不同型号的批量入口。该边界只描述当前可达的 UI 流程；不会为此删除旧代码、清理历史自定义灯具数据，或改变手动/自动分配、起始地址、通道模式、灯具数量上限和地址计算规则。

灯位图是独立入口。添加灯组前后的回归会检查已有灯组身份、逐台地址和布局位置保持不变；这不意味着旧灯位编辑面板的每种操作都由新界面等价替代。

## 本次决定与历史说明

2026-10-19 的本次产品决定排除“在一次添加操作中同时添加多个型号”。因此本批将 release-check 中只要求旧多型号/自定义添加入口可达的断言迁到当前单型号目录与待确认流程，并以显式历史自定义灯组数据 fixture 保留旧方案的计算、地址、复制和报告覆盖；fixture 不代表仍提供旧自定义创建入口。README 现行范围链接到本文。

P3 的 `tests/dmx-ui-refactor-2026-10-18/TEST-MIGRATION.md` 与报告作为历史记录保留；其中“批量添加”描述不构成当前多型号入口承诺。release-check 的旧灯位布局断言段（2354–2527）本批未迁移；完整 release 在 DMX 初始化 2305 性能断言处停止，因此后续布局断言未到达，本批不宣称其已迁移或通过。

## 验收覆盖

`tests/dmx-single-model-add-regression.cjs` 使用真实 DMX 地址页、灯位图页、工作区与地址计算模块，仅模拟微信平台边界。它覆盖：

- 从当前“＋ 灯组”到单型号目录、待确认预览和保存恢复的完整流程；确认前包括无效数量在内均不写入。
- 支持模式与数量对地址的影响。独立期望为已有两台 2 CH 灯具占用 A001、A003；新增三台 5 CH 灯具从 A005、A010、A015 起始，总范围 A005–A019。
- 手动 A 域剩余空间不足时拒绝预览确认，且不写入。
- 工作区 revision 冲突时保留最新已保存工作区，不以旧页面草稿覆盖它，并显示可重试草稿状态。
- 新增灯组后原有组 ID、灯具 ID、布局位置和确认后的数据恢复保持稳定。

该测试不使用历史 capture fixture，也不替代后续完整 release suite 或设备端验收。
