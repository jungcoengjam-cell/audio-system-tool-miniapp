# 重点页面性能测量

## 启用范围

- 开发版和体验版自动启用。
- 正式版自动关闭。
- 测量结果只保存在当前运行进程的内存中，并输出到调试控制台。
- 不写入本地存储，不采集用户信息，不发送网络请求。
- `utils/performance.js` 最多保留最近 120 条测量记录；汇总来自这个窗口，同一结束回调重复调用只计一次。跨页面长时间操作会挤出早期样本，应按页面分别留存控制台结果。
- 本文已按 2026-09-12 当前源码核对。下列日志名称以各页面和共享报告控制器中的实际 `startMeasurement` 调用为准，未启用的名称不会产生日志。

结果图片：

- LED：`LED大屏/长图绘制`、`LED大屏/长图导出`。
- 项目汇总：`项目详情/长图绘制`、`项目详情/长图导出`。

“绘制”记录的是源码中发出绘制指令的区间；“导出”记录的是导出调用到回调的区间。它们没有测量整页帧率，也不能单独证明用户操作到画面呈现的完整耗时。失败或失效请求可能不形成成功导出样本，应单独核对错误日志。

每次测量输出以 `[PERF]` 开头。离开已接入测量的页面时，会输出以 `[PERF汇总]` 开头的次数、平均值、P95 和最大值。

## 真机测试步骤

1. 使用真机调试或体验版打开小程序，记录设备、系统版本、基础库版本、源码版本及冷/热启动状态。使用测试项目和测试记录，避免修改正式项目。
2. 在“探索、工具、项目”三个 Tab 之间切换；在项目页切换“常用收藏、现场项目”，分别记录首次刷新、数据不变返回和测试记录变化后的刷新。
3. 从工具页进入摄像机模块，先确认收起的示意图没有 Canvas 查询；展开后连续修改区域宽度 5 次，再切换型号和场景，分别记录首次节点查询和缓存绘制。退出再返回、关闭再展开、改变屏幕尺寸时确认图仍能正常显示。
4. 进入会议室模块，分别查看报告型、圆桌和矩形桌方案，展开/收起示意并修改参数，分别记录计算、方案建模和绘图耗时。
5. 进入灯具地址码，使用测试方案分别设置 100、300、500 台。展开域和分组详情，滚动到末尾，跨页勾选后切换域/组，检查计数、显示地址和完成状态一致，再清空测试完成标记。
6. 在位置图中进行拖动、单指转双指、横竖屏往返及生成图片；检查恢复的位置、杆位统计、滚动和图片内容一致。当前没有独立的 DMX 位置图帧率埋点，不能用编址耗时代替拖动帧率。
7. 分别进入限幅器、声压级和增益架构，搜索并切换设备，再连续修改 5 次计算条件；进入产品资料库，筛选、追加列表、对比产品后返回，检查输入与结果对应。
8. 在 LED 和测试项目汇总中，分别验证首次生成、同输入再次打开、改变来源后重新生成及失败重试。对比首次绘图/导出与缓存路径；检查旧图片不能覆盖当前方案。
9. 离开页面查看控制台并筛选 `PERF汇总`。项目页和会议室等在隐藏时汇总，摄像机、DMX、产品库等在卸载时汇总；仅切至后台不保证所有模块立刻输出汇总。
10. 同一套操作至少执行 5 次，首次结果单独记录，同时保留样本数、平均值、P95、最大值和明显卡顿现象；样本少时不要仅凭 P95 宣称性能稳定。不同设备、场景和缓存状态分别比较。

## 项目内部判断线

以下数值用于本项目迭代判断，不是微信平台强制标准：

| 测量点 | 良好 | 建议继续优化 |
| --- | ---: | ---: |
| 项目页工作区刷新总耗时 | ≤ 50 ms | P95 > 100 ms |
| 摄像机初始化总耗时 | ≤ 100 ms | P95 > 180 ms |
| 摄像机核心几何计算 | ≤ 10 ms | P95 > 20 ms |
| 摄像机 setData 视图更新 | ≤ 30 ms | P95 > 60 ms |
| 摄像机 Canvas 节点查询 | ≤ 50 ms | P95 > 100 ms |
| 摄像机 Canvas 缓存绘制 | ≤ 16.7 ms | P95 > 33 ms |
| DMX 核心编址 | ≤ 10 ms | P95 > 20 ms |
| DMX 结果视图更新 | ≤ 50 ms | P95 > 100 ms |
| DMX 首批逐台地址展开 | ≤ 100 ms | P95 > 150 ms |
| 三个音频页初始化总耗时 | ≤ 80 ms | P95 > 150 ms |
| 三个音频页核心计算 | ≤ 5 ms | P95 > 15 ms |
| 三个音频页 setData 视图更新 | ≤ 30 ms | P95 > 60 ms |
| 三个音频页设备搜索过滤 | ≤ 5 ms | P95 > 15 ms |
| 三个音频页设备搜索视图更新 | ≤ 30 ms | P95 > 60 ms |

如果核心计算很快而 `setData` 或 Canvas 较慢，应继续优化视图层；如果全部在良好范围内，不建议为了微小收益继续增加代码复杂度。
